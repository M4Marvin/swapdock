# Uninstall

`install/uninstall-swapdock.sh` removes the host integration that
`install-swapdock.sh` added. It never stops or removes app containers, and it
never removes the generated front-door nginx config.

There is no `swapdock uninstall` CLI command yet (G1.3); use the script from a
dist tree or from a source checkout at `install/uninstall-swapdock.sh`.

## Usage

```bash
# From a source checkout:
sudo bash install/uninstall-swapdock.sh
# or from a dist tree:
sudo bash swapdock-dist/uninstall-swapdock.sh

# Preview without changing anything (no root required):
bash install/uninstall-swapdock.sh --dry-run

# Also remove state and logs:
sudo bash install/uninstall-swapdock.sh --purge
```

The script requires root unless `--dry-run` is used. It is idempotent: missing
files are reported as `absent` and skipped.

## What it removes

| Path | Behavior |
|---|---|
| `/usr/local/bin/swapdock` | Removed. A `.bak` from the installer is **not** restored and is left in place. |
| `/etc/sudoers.d/swapdock` | Removed. `.bak` is left in place. |
| `/etc/logrotate.d/swapdock` | Removed. `.bak` is left in place. |
| `/etc/systemd/system/swapdock.service` | If present: stopped, disabled, removed, then `systemctl daemon-reload`. |
| `/etc/swapdock/api.env` | Removed when present (created by `--with-service`). It contains `SWAPDOCK_API_TOKEN`; do not leave a stale credential behind. |
| `/etc/nginx/conf.d/00-swapdock-http.conf` | Removed, or restored from `.bak` when one exists. |
| `/etc/nginx/snippets/proxy-common.conf` | Removed, or restored from `.bak` when one exists. |
| `/etc/nginx/snippets/spa-fallback.conf` | Removed, or restored from `.bak` when one exists. |

## What it keeps by default

- `/srv/swapdock` — the registry, overrides, green state, backups.
- `/var/log/swapdock` — the JSONL run log.
- `/usr/local/bin/swapdock.bak` and the other `.bak` files.
- The installer's `/root/nginx-pre-swapdock-*.tgz` backups.
- Every app container and Docker volume.
- `/etc/nginx/conf.d/front-door.conf` (generated by `swapdock apply`).

`--purge` removes `/srv/swapdock` and `/var/log/swapdock` as well. It still
does not touch containers, Docker volumes, `/etc/nginx/conf.d/front-door.conf`,
or the `.bak` files.

## The generated front-door config

`/etc/nginx/conf.d/front-door.conf` is written by `swapdock apply`, not by the
installer. If you remove the snippets but leave that file in place, it can
reference files that no longer exist. The uninstaller prints a warning and runs
`nginx -t` (test only, no reload):

- running nginx keeps serving its loaded configuration;
- a future `nginx -s reload` will fail until you remove or replace the generated
  file.

Back it up before removing it:

```bash
sudo cp -a /etc/nginx/conf.d/front-door.conf /root/front-door.conf.$(date +%F-%H%M)
sudo rm /etc/nginx/conf.d/front-door.conf
sudo nginx -t
```

If you keep using the apps outside swapdock, you need your own nginx server
blocks. Removing swapdock does not create them.

## Manual leftovers

The script cannot safely reverse everything:

- **`/etc/swapdock/`:** the uninstaller removes `api.env` but leaves the
  directory (it may contain operator files). Remove it only if it is empty.
- **`adm` group:** the installer adds your user to `adm`. The uninstaller does
  not remove it because it cannot know whether it was already a member. Remove
  it yourself with `sudo gpasswd -d <user> adm` if appropriate.
- **`.bak` files:** inspect and delete them after you are satisfied. They are
  the only copy of the pre-install files.
- **`/root/nginx-pre-swapdock-*.tgz`:** the installer's full nginx backup.
- **Docker images, volumes and containers:** uninstalling swapdock does not
  prune them. Use `docker` deliberately; the tool's own `prune` command is for
  release images and does not exist as an uninstall action.
- **Cloudflare/tunnel routes:** swapdock never edits the tunnel; remove those
  rules yourself if you no longer need them.

## Verify the host is clean

```bash
command -v swapdock || echo "binary gone"
sudo test ! -e /etc/sudoers.d/swapdock && echo "sudoers gone"
sudo test ! -e /etc/logrotate.d/swapdock && echo "logrotate gone"
sudo nginx -t
```

If you used `--purge`, also confirm `/srv/swapdock` and `/var/log/swapdock` are
gone. Do not expect the apps to still be routed by nginx after you remove the
generated front door.
